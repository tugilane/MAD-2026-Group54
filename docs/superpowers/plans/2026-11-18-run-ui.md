# Run UI Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. Implement and verify each task before moving on.

**Goal:** Connect the existing running backend to a usable Run screen and completion summary.

**Architecture:** Keep tracking and persistence in the foreground service. A Compose route handles Android permissions and commands, a ViewModel combines durable and live run state, and a stateless screen displays it using existing app components.

**Tech Stack:** Kotlin, Jetpack Compose, existing lifecycle ViewModel and Room dependencies.

**Spec:** `docs/stage-2-development-doc.md`, section 4.3; user approved the Run UI scope in this conversation.

## Global Constraints

- Continue on `feat/running-flow`; the tested backend checkpoint is `ec01f7b` and is already pushed.
- Use existing components, typography, colours and unit settings; add no dependencies.
- Do not automatically resume an interrupted run or discard unsaved data.
- The reviewed UI and follow-up fixes are authorized for commit and push by the user's shipping request.

## Review Focus

- Permission denial, approximate-only location and disabled GPS must leave a usable retry/settings path.
- Notification permission denial must allow a run with precise location permission.
- Rotation and notification entry must keep the same session and preserve the completion summary.
- Saving failure must retain the run and permit a successful retry.
- Leaving the screen must explicitly offer continued background tracking or confirmation before discarding.
